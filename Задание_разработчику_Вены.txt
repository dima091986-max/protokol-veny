────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 1.1. Подраздел «Дополнительно» в тексте протокола
Приоритет: ВЫСОКИЙ
────────────────────────────────────────────────────────────────────────────

ТЕКУЩЕЕ ПОВЕДЕНИЕ
В функции generateLimbReport() трофические изменения, отёк и язва
добавляются в общий массив parts[] наравне с данными БПВ, МПВ,
перфорантов и варикозных узлов. Подзаголовок «Дополнительно:» и
визуальный разделитель отсутствуют.

ТРЕБУЕМОЕ ПОВЕДЕНИЕ
Трофические изменения, отёк и язва должны выводиться в отдельном
подразделе «Дополнительно:» после основного блока поверхностных вен.

Ожидаемая структура протокола:
  ПОВЕРХНОСТНЫЕ ВЕНЫ:
  - Несостоятельность СФС...
  - СПС несостоятельно. МПВ варикозно изменена...
  - Варикозно расширенные вены до 6 мм, голень...

  Дополнительно:
  - Трофические изменения: гиперпигментация, липодерматосклероз.
  - Локальный отёк.
  - Зажившая трофическая (венозная) язва.

ЧТО НУЖНО СДЕЛАТЬ
В конце функции generateLimbReport(), после блока варикозных узлов,
собрать отдельный массив additionalParts[]. Если он непустой —
добавить подзаголовок и его содержимое в основной вывод.

Пример реализации:
──────────────────────────────────────────────────────
const additionalParts = [];

// Трофические изменения
if (findings.trophic_changes && findings.trophic_changes.length > 0) {
    additionalParts.push(
        'Трофические изменения: ' + findings.trophic_changes.join(', ') + '.'
    );
}

// Отёк
if (extra.edema && extra.edema !== 'none') {
    const edemaLabel = extra.edema === 'peripheral'
        ? 'Периферический отёк.'
        : 'Локальный отёк.';
    additionalParts.push(edemaLabel);
}

// Язва
if (extra.ulcer && extra.ulcer !== 'none') {
    const ulcerLabel = extra.ulcer === 'healed'
        ? 'Зажившая трофическая (венозная) язва.'
        : 'Открытая трофическая (венозная) язва.';
    additionalParts.push(ulcerLabel);
}

// Вывод подраздела
if (additionalParts.length > 0) {
    parts.push('');
    parts.push('Дополнительно:');
    parts.push('-'.repeat(60));
    additionalParts.forEach(line => parts.push('- ' + line));
}
──────────────────────────────────────────────────────

ТРЕБОВАНИЯ К РЕАЛИЗАЦИИ
1. Порядок строк в подразделе: трофические изменения → отёк → язва.
2. Подраздел НЕ выводится, если все три поля пусты / в значении «нет».
3. Логика для правой и левой конечности идентична.


────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 1.2. Атрибут генеза отёка
Приоритет: ВЫСОКИЙ
────────────────────────────────────────────────────────────────────────────

ТЕКУЩЕЕ ПОВЕДЕНИЕ
Форма содержит поле edema со значениями none / peripheral / local.
Генез отёка (венозный / невенозный / не уточнён) не фиксируется.
C3 присваивается автоматически при peripheral без учёта этиологии.

ТРЕБУЕМОЕ ПОВЕДЕНИЕ
Добавить подполе «Генез отёка» (select или radio-группа):
  - Венозный
  - Не уточнён (по умолчанию)
  - Невенозный

Логика CEAP:
  - «Венозный» или «Не уточнён» → C3 присваивается (текущее поведение)
  - «Невенозный» → C3 НЕ присваивается,
    но строка об отёке остаётся в разделе «Дополнительно»

ЧТО НУЖНО СДЕЛАТЬ
1. Добавить новый элемент формы edema_origin (select/radio)
   рядом с существующим блоком отёка.
2. Передавать значение edema_origin в объект clinical_extra.
3. В функции computeLimbCEAP() изменить условие присвоения C3:

   Было:
     if (extra.edema === 'peripheral') cClasses.push(3);

   Стало:
     if (extra.edema === 'peripheral' && extra.edema_origin !== 'non-venous') {
         cClasses.push(3);
     }

4. Поле edema_origin отображать только при edema !== 'none'.


────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 1.3. Предупреждение при C3–C6 + статус A (асимптомная)
Приоритет: СРЕДНИЙ
────────────────────────────────────────────────────────────────────────────

ТЕКУЩЕЕ ПОВЕДЕНИЕ
Функция validateForm() существует, но не проверяет комбинацию
«трофические изменения / отёк / язва + статус A».

ТРЕБУЕМОЕ ПОВЕДЕНИЕ
Если для конечности вычислен CEAP C3 и выше, а статус симптомности
указан «A» (асимптомная) — выводить предупреждение врачу.

ЧТО НУЖНО СДЕЛАТЬ
Добавить следующую проверку в тело validateForm() для каждой конечности:

──────────────────────────────────────────────────────
['right', 'left'].forEach(side => {
    const limbData = data.limbs[side];
    if (!limbData) return;

    const ceap = computeLimbCEAP(limbData);
    const label = side === 'right' ? 'правой' : 'левой';

    if (ceap.cClass >= 3 && ceap.symptom === 'A') {
        warnings.push(
            'Проверьте данные ' + label + ' конечности: ' +
            'трофические изменения / отёк / язва (C≥3) обычно ' +
            'сопровождаются симптоматикой. Возможно, следует указать «S».'
        );
    }
});
──────────────────────────────────────────────────────

ПРИМЕЧАНИЕ
Предупреждение информационное (не блокирует сохранение/печать).
Вывод — в том же месте, что и остальные предупреждения validateForm().

────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 2.1. Рекомендации при язве (C5/C6) — КРИТИЧНО
Приоритет: ВЫСОКИЙ
────────────────────────────────────────────────────────────────────────────

ПРОБЛЕМА
Функция hasTrophicChanges() проверяет только findings.trophic_changes[].
При наличии язвы (C5 — зажившая, C6 — открытая) рекомендации
по компрессии и местному лечению НЕ срабатывают, хотя при язве
они являются абсолютным клиническим показанием.

ИСПРАВЛЕНИЕ
Расширить функцию hasTrophicChanges() — добавить проверку поля ulcer:

──────────────────────────────────────────────────────
function hasTrophicChanges(data) {
    const hasUlcer = (d) =>
        d && d.clinical_extra && d.clinical_extra.ulcer !== 'none';

    return (
        (data.limbs.right && (
            (data.limbs.right.findings?.trophic_changes?.length > 0) ||
            hasUlcer(data.limbs.right)
        )) ||
        (data.limbs.left && (
            (data.limbs.left.findings?.trophic_changes?.length > 0) ||
            hasUlcer(data.limbs.left)
        ))
    );
}
──────────────────────────────────────────────────────

ЗАДАЧА 2.2. Рекомендация ЭВЛО при рефлюксе МПВ без галочки «Несостоятельность СПС»
Приоритет: ВЫСОКИЙ
────────────────────────────────────────────────────────────────────────────

ПРОБЛЕМА
hasIncompetentSPS() проверяет только conditions.includes('incompetent').
Если врач отметил только «Рефлюкс» (conditions: ['reflux']) и ввёл
числовое значение рефлюкса > 0.5 сек — функция вернёт false,
рекомендация ЭВЛО не появится.

Медицинская логика: рефлюкс по МПВ > 0.5 сек является самостоятельным
клиническим показанием к вмешательству, независимо от галочки «Несостоятельность».

ИСПРАВЛЕНИЕ
──────────────────────────────────────────────────────
function hasIncompetentSPS(limbData) {
    const mpv = limbData?.findings?.mpv;
    if (!mpv) return false;
    return mpv.conditions?.includes('incompetent') ||
           (mpv.reflux > 0.5);
}
──────────────────────────────────────────────────────


────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 2.3. Несогласованность чекбокса «Рефлюкс» МПВ и числового поля
Приоритет: СРЕДНИЙ
────────────────────────────────────────────────────────────────────────────

ПРОБЛЕМА
Врач может отметить чекбокс «Рефлюкс» (value="reflux") в блоке МПВ,
но не заполнить числовое поле рефлюкса.
Результат: CEAP засчитает C2 (через conditions.includes('reflux')),
но в тексте протокола строка «Патологический рефлюкс по стволу X сек»
не выведется. Пользователь получит CEAP с C2 без числового
подтверждения в тексте — потенциальное расхождение.

РЕКОМЕНДАЦИЯ
При установке/снятии чекбокса «Рефлюкс» в блоке МПВ — подсвечивать
числовое поле рефлюкса как обязательное (мягкая валидация).
Реализация: добавить CSS-класс «required-soft» + проверку в validateForm()
с некритичным предупреждением (не блокирующим сохранение).


────────────────────────────────────────────────────────────────────────────
ЗАДАЧА 2.4. Граничный случай: МПВ варикозно изменена + СПС состоятельно
Приоритет: НИЗКИЙ (тестирование)
────────────────────────────────────────────────────────────────────────────

ОПИСАНИЕ
В generateLimbReport() строка «СПС состоятельно» добавляется при
spsIncompetent === false. При заполненных данных МПВ (варикозная
трансформация + диаметры) текст будет содержать:
«СПС состоятельно. МПВ варикозно изменена.»

Медицински это корректно, однако рекомендуется вручную протестировать
данный граничный случай и убедиться, что оба факта выводятся
в одной строке с правильной пунктуацией.

ДЕЙСТВИЕ
Тест-кейс: заполнить данные МПВ (варикозная трансформация = да,
диаметр = 7 мм) + СПС состоятельно → проверить текст протокола.
